# Berlin Urban Intelligence v1.0.0

Released: 2026-09-16

Version 1.0.0 is the first stable release of Berlin Urban Intelligence, a research-oriented, agent-extensible urban intelligence and digital-twin integration platform for Berlin.

The release marks the point at which the repository's declared v1 scope has passed its evidence-driven completion matrix. It does not change the project's research orientation into a claim of municipal, safety-critical or production-scale operational authority.

## What is in v1.0.0

### Canonical urban state and source handling

The platform normalizes heterogeneous urban inputs into typed canonical contracts that preserve epistemic/data state, UTC timestamps, units, CRS, quality, freshness and provenance. Provider acquisition is separated from request handling, persisted snapshots are validated before replacement, and invalid replacements retain the last-known-good in-process state.

Live acquisition covers configured Berlin air-quality, DWD weather and VBB GTFS-Realtime inputs. Slow-changing reference acquisition covers configured official facilities, selected climate-analysis layers, VBB static GTFS and optional OpenStreetMap road topology. Missing or failed providers remain explicit; the platform does not fabricate production measurements or a synthetic replacement road network.

### Agent-extensible architecture

Six real agents are included in the release: Live State, Mobility, Exposure, Heat, Energy and Resilience. Their descriptors expose domain, capabilities, dependencies and health. Cross-agent execution is resolved through registry-driven deterministic capability/dependency orchestration rather than hidden coupling inside individual agents.

The architecture intentionally keeps source adapters, canonical contracts, persisted state, domain agents, derivations, orchestration and presentation separable so additional domain agents can be introduced without collapsing provenance or source-specific semantics.

### Derived and cross-domain information

Derived information is first-class persisted state with definitions, dependency DAGs, upstream lineage, producer/algorithm versions, quality/freshness propagation and incremental recomputation.

Two source-backed cross-domain products are verified in v1.0.0:

- Heat + Air Quality context;
- Mobility + Air Quality context.

They retain independent source timestamps and provenance. Their interpretation is descriptive only: they are not causal, correlation, exposure or universal-score models.

### Energy workflow

The energy subsystem provides leakage-safe chronological evaluation against persistence and seasonal baselines plus Ridge and gradient-boosting candidates. Persisted forecast artefacts are bound to the evaluated dataset fingerprint and model metadata before the Energy Agent accepts them.

The reproducible real-data evidence uses the clean official 2024 Stromnetz Berlin high-voltage annual load curve. The inspected 2025 publications containing an upstream `#BEZUG!` timestamp block are rejected rather than silently repaired. The accepted historical source contains 35,136 validated quarter-hour observations.

This evidence is deliberately scoped: it is historical high-voltage network load and is not presented as current total Berlin demand or as a live grid-control forecast.

### Resilience and real road-network evidence

The resilience subsystem supports multi-edge weighted routing, route comparison, facility snapping, accessibility analysis and immutable disruption overlays.

Optional OSM acquisition remains separate from deterministic PR CI. Live run `35091544852` on 2026-09-16 tested `Mitte, Berlin, Germany` with network type `drive`. Two public Overpass delivery endpoints exceeded their attempt budgets; those failures were retained as evidence. `https://overpass-api.de/api` then returned a real graph that passed the strict readiness contract:

- 740 canonical nodes;
- 1,800 canonical edges;
- `OpenStreetMap contributors` / ODbL 1.0 provenance;
- provenance-visible OSMnx speed/travel-time imputation;
- `synthetic_fallback=false`.

The existing `ResilienceAgent` completed a baseline route from `osm-node:10087214573` to `osm-node:13043292535` at approximately 2.139 seconds. This proves point-in-time compatibility and routing readiness, not permanent public Overpass availability.

### Semantic layer and APIs

Validated state can be projected to RDF using the project ontology together with PROV-O/SOSA concepts. The release includes SHACL artefacts, derived lineage projection, version-controlled SPARQL examples and bounded semantic relationship inspection.

FastAPI exposes system, source, agent, domain, reference, scenario, derived, dependency, semantic, map and resilience surfaces. Complete graph serialization remains a bulk/research operation rather than a high-QPS production endpoint.

### Dashboard

The React/TypeScript/MapLibre dashboard provides map/reference inspection, provenance inspection, source and agent health, derived/dependency inspection, deterministic workflows, scenario controls and baseline-versus-disruption resilience routing.

Principal workflows have a keyboard-accessible baseline, including a coordinate-driven non-pointer routing path. Representative composed states are exercised with Playwright and automated Axe scanning for configured critical/serious WCAG A/AA findings. This is practical regression evidence, not a formal WCAG conformance statement.

### Security, observability and performance evidence

The v1 baseline includes loopback-only default exposure, hardened containers, browser security headers, exception-message redaction, vulnerability-reporting documentation and separate dependency-audit workflows.

Structured operation events cover requests, source refresh, snapshot reload, derivation refresh and scenarios using allow-listed low-cardinality fields and correlation identifiers.

Performance evidence uses reproducible representative fixtures and bounded map responses. Hosted-runner latency/memory measurements are engineering evidence only and are not a production-capacity guarantee.

## Running v1.0.0

The default local composition is:

```bash
docker compose up --build
```

The dashboard is then served at `http://localhost:8080` and FastAPI/OpenAPI at `http://localhost:8000/docs`.

Optional OSM reference acquisition is explicit:

```bash
python scripts/refresh_reference.py --with-osm
```

Provider-dependent analytical capabilities remain unavailable when their required validated persisted inputs do not exist.

## Upgrade and compatibility notes

v1.0.0 is the first stable Semantic Versioning release, so there is no earlier stable compatibility line to migrate from. Existing pre-1.0 persisted/runtime artefacts should still be treated according to their executable validation contracts rather than assumed compatible solely from file names or timestamps.

Future breaking changes to public stable contracts should require a new major version. Evidence and provider snapshots remain point-in-time records and are not embedded as permanent production fallbacks.

## Limitations

Version 1.0.0 does **not** claim:

- permanent availability of Berlin, VBB, DWD, Stromnetz Berlin, OpenStreetMap or public Overpass endpoints;
- municipal operational/control authority or suitability for safety-critical decisions;
- authenticated multi-tenant/public-cloud production readiness;
- a universal Berlin score or causal cross-domain inference;
- calibrated energy prediction intervals or a live total-demand/grid-control forecast;
- formal WCAG conformance;
- production-scale throughput/capacity guarantees from hosted CI benchmarks;
- persistent production-grade semantic-store operation;
- distributed/federated independently deployed agents or protocol-level version negotiation.

These boundaries are intentional. Missing evidence remains visible as unavailable, conditional or future work rather than being converted into completion claims.
