# Data processing

This page traces the implemented transformations from external input to canonical state.

## Live refresh

`RefreshCoordinator.refresh()` processes Berlin air quality, DWD and VBB independently.

### Air quality

1. Fetch current LQI payload.
2. Extract/parse station records.
3. Reject a response with no usable records.
4. Convert records through `ExposureAgent.ingest_lqi_records()`.
5. Replace only prior observations produced by the exposure agent.
6. Record source success with retrieval and latest observation timestamps.

On failure, the previous exposure observations remain when previous runtime state was supplied; source availability becomes unavailable and an error code is recorded.

### DWD meteorology

1. Fetch the configured 10-minute record.
2. Parse provider missing-value conventions.
3. Convert available variables into canonical observations through `HeatAgent`.
4. Replace only prior heat-agent observations.
5. Preserve provider QC information in canonical quality/provenance.

### VBB GTFS-Realtime

1. Download protobuf feed.
2. Decode feed timestamp and trip updates.
3. Require an explicit source timestamp.
4. Build `TransitUpdate` records and summarize them into `MobilitySnapshot`.
5. Record source status independently of observation content.

An empty update set does not become a normal-service conclusion; the snapshot quality is unknown.

## Source failure classification

The live coordinator currently maps:

- selected `ValueError`, `KeyError` and `TypeError` failures -> `SCHEMA_CHANGED`;
- GTFS-Realtime decoder-related runtime failure -> `DECODER_UNAVAILABLE`;
- other selected runtime model failures -> `MODEL_UNAVAILABLE`;
- remaining exceptions -> `SOURCE_UNAVAILABLE`.

These codes are operational diagnostics, not universal exception taxonomies.

## Reference processing

`ReferenceRefreshCoordinator` acquires official facilities and selected Climate Analysis layers. Geometry/properties are normalized without inferring missing operational semantics.

The climate path repairs invalid-but-repairable geometries with `shapely.make_valid`; repaired features are marked `suspect` and the transformation is recorded in provenance.

`ReferenceAcquisitionCoordinator` also integrates static VBB GTFS and, when requested, an OSM road network. Last-known-good reference state can be carried forward for independently failed sources.

## Facility normalization

Official hospital/fire-station GeoJSON is converted to `CriticalFacility`. The registry attempts to derive a display name from known source property keys but retains source identifiers. The resulting facility expresses identity/location only; no opening/capacity/operational field is invented.

## Network processing

OSM network processing is optional. Network nodes/edges become canonical `NetworkNode`/`NetworkEdge` objects. If OSM speed/travel-time values are incomplete, derived speed imputation occurs only when explicitly enabled and must remain provenance-visible.

Facility snapping is a downstream resilience derivation, not ingestion. Coordinates are transformed to EPSG:25833, nearest-node distance is calculated in metres, and facilities beyond the configured threshold are left unsnapped.

## Energy processing

1. Load an explicit local CSV or verified Stromnetz Berlin HTTPS URL.
2. Parse using explicit timestamp/value column names, unit, delimiter and source timezone.
3. Convert timestamps to UTC and reject duplicate/non-monotonic timestamps or non-finite target values.
4. Build lag/rolling/time features using only information available before the target time.
5. Remove rows lacking complete features.
6. Split chronologically into train/test partitions.
7. Evaluate persistence, seasonal-naive, Ridge and histogram gradient boosting on the same holdout.
8. Select the minimum-MAE candidate, then RMSE, then a deterministic simplicity order for exact ties.
9. Train the selected model on usable history and forecast one regular-cadence interval ahead.
10. Persist evaluation and forecast with a SHA-256 dataset-content fingerprint.

No calibrated uncertainty interval is generated by the current pipeline.

## Semantic processing

Canonical objects can be projected to RDF. The graph code creates project resource IRIs from canonical identifiers, uses SOSA for observation relationships and PROV-O for source/activity lineage, and serializes source properties/geometry where appropriate.

## No silent semantic promotion

Processing must not silently:

- turn missing values into zero;
- treat a repaired geometry as pristine without quality/provenance annotation;
- treat source/model features as observations;
- treat an inferred speed as observed speed;
- reuse model metrics for a different dataset fingerprint; or
- overwrite baseline state with scenario output.
